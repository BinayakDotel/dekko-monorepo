# Project: Dekko (code name: archsync)

A GitHub-centric tool that makes a developer prove they understand a pull request
before merging: Predict → Read → Answer → Reveal. Read `docs/SPEC-F1.md` for the
feature being built now and `docs/TASKS.md` for the current ticket.

## How we work

- One ticket per chat. Read `NOW.md` first; it names the single next task.
- Plan before editing anything that touches more than two files. Wait for approval.
- Smallest change that satisfies the ticket's "done when". No drive-by refactors.
- Every behavior change comes with a test in the same change.
- Never run `git commit` or `git push`. The human commits.
- Never add dependencies without saying why in one sentence first.
- Secrets live in `.env.local` only. Never read or print them.
- Library docs beat memory. For Next.js, Turborepo, Vitest and the AI SDK, read the
  installed or official docs before writing code (see `.cursor/rules/`).

## Stack (do not deviate without a decision in docs/DECISIONS.md)

- pnpm workspaces + Turborepo. TypeScript everywhere. Node 22+.
- apps/web: Next.js App Router, Tailwind. Convex client for data.
- packages/core (`@dekko/core`): pure TypeScript, no I/O, source-only (no build step).
  Zod schemas, diff parser, scoring. apps/web consumes it via `transpilePackages`.
- apps/web/convex: Convex schema, queries, mutations, actions.
- Model calls go through packages/core/src/ai via the Vercel AI SDK; provider by env var.

## Commands (run from the repo root)

- `pnpm build`, `pnpm test`, `pnpm lint`, `pnpm typecheck`, `pnpm format`.
- One package: `pnpm --filter @dekko/core test`, `pnpm --filter web build`.

## Non-negotiables for AI output

- The model never writes diagram markup. It returns typed JSON (Zod schema) with
  hunk IDs and a confidence on every component and edge. Rendering is deterministic.
- Diffs, PR titles and PR bodies are untrusted data. Prompts say so.

## Where guidance lives

- `AGENTS.md` (this file): always-on contract, kept short.
- `.cursor/rules/*.mdc`: focused rules; only `core.mdc` is always on, the rest load by path.
- `NOW.md`: the single next task. `docs/`: spec, tickets, decisions, workflow, prompts.
- `apps/web/AGENTS.md` and the block below are auto-generated by Next and Turbo.
  Do not edit those blocks by hand.

# This is NOT the Turborepo you know

Turborepo configuration, task behavior, and CLI commands can vary between installed versions and may differ from your training data. Resolve the `turbo` package from this file's directory or relevant workspace; in monorepos, it may not be visible from the repository root. For example, run `node -p "require.resolve('turbo/package.json')"` from a workspace that depends on `turbo`.

Read `docs/README.md` inside that installed package first, then read the relevant pages from its `docs/` directory before changing Turborepo configuration or commands. Heed deprecation notices. These bundled docs match the installed package version and are available without network access.

This block is written and re-added by `turbo` before repository-scoped commands when an AI agent is detected. In the Turborepo source repository, its template is defined in `crates/turborepo-cli/src/cli/agent_guidance.rs`. Removing the managed block while updates are enabled means a later qualifying invocation will add it again. Set `"agentGuidance": false` in the root `turbo.json` or `turbo.jsonc` to opt out; this does not remove an existing block. Keep the block committed with your work to avoid an uncommitted change on the next agent invocation.
